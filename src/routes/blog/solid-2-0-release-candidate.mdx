Solid 2.0 is the next major version of Solid. It keeps the fine-grained reactivity you know, and tightens up how writes, effects, async data and mutations fit together. This post is a short tour of the headline changes. It is not exhaustive: the [migration guide](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md) is the complete reference, and the [Solid 2.0 docs](https://v2.solidjs.com) cover the details.

## Writes are batched

Writes are batched in a microtask, so a setter does not change what a read returns until the batch flushes. `flush()` applies pending writes early. The old `batch` function is gone because batching is now the default.

```js
setCount(1);
count(); // still 0
flush();
count(); // now 1
```

## Effects have two halves

`createEffect` separates a compute phase, which tracks dependencies, from an apply phase, which performs side effects.

```js
createEffect(
  () => name(),
  value => {
    el().title = value;
  }
);
```

Because the compute phase declares what an effect depends on, the `on` helper is no longer needed.

## Async is built into memos

`createResource` is replaced by an async `createMemo`. Consumers wrap the read in `Loading` for initial readiness, and `isPending` reports in-flight input changes.

```js
const user = createMemo(() => fetchUser(id()));
```

```jsx
<Loading fallback={<Spinner />}>
  <Profile user={user()} />
</Loading>
```

`Suspense` becomes `Loading`, and `ErrorBoundary` becomes `Errored`, whose fallback receives an accessor.

```jsx
<Errored fallback={err => <p>{err().message}</p>}>
  <Child />
</Errored>
```

## One `For`

`Index` is removed. Use `For` with `keyed={false}` instead: the callback receives an item accessor and a numeric index.

```jsx
<For each={items()} keyed={false}>
  {(item, i) => <Row item={item()} index={i} />}
</For>
```

## Stores take drafts

Store setters now receive a mutable draft, so `produce` is no longer needed.

```js
setStore(s => {
  s.user.address.city = "Paris";
});
```

## Actions and optimistic updates

Mutations are wrapped in `action(...)`. Optimistic UI uses `createOptimisticStore`, and `refresh(...)` reconciles derived reads with the source of truth.

```js
const addTodo = action(function* (todo) {
  setOptimisticTodos(s => s.list.push(todo));
  yield api.addTodo(todo);
  refresh(todos);
});
```

## What else is removed or renamed

The migration guide lists these as removed: `createResource`, `batch`, `createComputed`, `on`, `onError` and `catchError`, `produce`, `createMutable` and `modifyMutable`, and `Context.Provider` (the context is now used directly as the provider). Renames include `mergeProps` to `merge`, `splitProps` to `omit`, `onMount` to `onSettled`, and `unwrap` to `snapshot`.
